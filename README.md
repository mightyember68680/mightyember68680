# Hey, I'm here

Software engineer who spends most days writing Python, wiring up automation scripts, and keeping Linux boxes happy. I care about systems that stay out of the way and do their job without drama.

## What I actually work on

Most of my time goes into Python tooling and automation. Small scripts that clean up repetitive work, glue services together, or make deployments less painful. I prefer clear, readable code over clever one-liners. If a script needs a comment explaining why it exists, the design probably needs another pass.

Linux is the environment I trust. Servers, local machines, containers—whatever the job needs. I keep configs simple, prefer systemd where it makes sense, and try not to over-engineer the monitoring stack. Good logs beat fancy dashboards most of the time.

## Day-to-day

- Writing and reviewing Python for internal tools and side projects
- Automating the boring parts of builds, tests, and deploys
- Tuning Linux environments so they stay stable under load
- Thinking about how pieces fit together before writing the first line

I like software engineering that prioritizes maintainability. Code should be easy to change six months later. That means boring solutions, explicit error handling, and documentation that matches reality.

## Tools I reach for

Python is the default. Requests, pathlib, argparse, and the standard library cover a surprising amount. When something needs to run on a schedule or respond to events, I reach for simple automation rather than heavy frameworks.

On the system side: bash when it's the right tool, Python when the logic grows, and a healthy respect for what the kernel and userspace already provide.

## Contact

Open an issue on one of the repos if you want to talk shop about Python, automation patterns, or Linux ops. Happy to exchange notes on practical approaches that have survived real use.

No flashy claims here—just code that tries to stay useful.
